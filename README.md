# AI Solution Workflow

面向商机阶段客户解决方案设计的 Codex Skill，通过“总控＋五个子 Skill”，在一个项目、一个对话框中完成从需求理解到可编辑 PPT 制作的工作流。

当前版本：**V0.6**

## 工作流程

需求整理 → 行业调研与人工阅读 → 内部能力研究 → 确认建设方向 → 文字方案 → 页面规划与原型 → 可编辑 PPT → 人工补充素材与最终审核

流程支持研究与讨论中的反馈调整，也支持从已有成果继续推进。

## Skill 结构

```text
solution-workflow/
├── SKILL.md                         总控入口与阶段路由
├── assets/
│   └── project-brief.md              项目需求模板
├── references/
│   └── project-files.md              项目文件组织与成果交接
└── skills/
    ├── solution-industry-research/   行业调研与人工笔记
    ├── solution-capability-scope/    内部研究与建设方向
    ├── solution-written-plan/        完整文字方案
    ├── solution-page-prototype/      页面规划与视觉原型
    └── solution-ppt-production/      可编辑 PPT 制作
各子 Skill 包含独立的 SKILL.md，按需配置调研条目模板、布局指引和 PPT 制作 prompt。总控负责流程推进，子 Skill 负责具体环节，参考文件提供执行细则。
资料与项目管理
本版本采用本地文件管理，方法、共享资料和项目成果分别保存。
区域	内容与管理方式
Skill 文件夹	保存工作方法、执行规则及模板，由版本更新统一维护。
REFERENCE/SHARE	保存公司产品资料、通用案例、PPT 模板等复用材料，由人工补充，各项目按需读取。
REFERENCE/PROJECT_*	每个项目独立保存需求、调研、建设方向、文字方案、原型及 PPT。


项目内部按工作阶段组织：
PROJECT_项目名/
├── 00_项目需求/
├── 01_行业调研/
├── 02_内部调研与建设方向/
├── 03_文字方案/
├── 04_PPT页面原型/
│   ├── 页面规划.md
│   └── work/
│       ├── draft/
│       └── confirmed/
├── 05_PPT制作/
└── 06_最终交付/
调研笔记与内部研究共同支持方案设计；文字定稿转为页面规划和原型；确认原型作为正式 PPT 的制作依据。持续更新现有成果，保留人工笔记与已确认内容。
协作方式
- 行业调研生成带人工阅读区的 Word 笔记，用户填写后重新读取。
- 内部研究结合公司资料，说明候选方向能否实现、如何实现及可扩展的效果。
- 文字方案默认采用四章结构，可按项目需要调整。
- 页面原型在对话内展示，完整承接页面内容，并针对各页参考布局、设计构图。
- 正式 PPT 应用公司模板，保留可编辑文字、图形和关系，缺少的真实素材预留位置。
- 人工参与方向选择、成果确认、素材补充及最终审核。
使用前，需按实际环境调整总控及子 Skill 中的本地资料路径，并准备项目需求和相关共享资料。
版本说明
V0.5 建立完整工作流，明确总控与五个子 Skill 的职责、文件组织和阶段交接。

V0.6 延续 V0.5 的设计，根据两个真实项目的反馈，补强内外调研衔接、研究笔记回读及第二章写作指引；完善原型内容承接、逐页布局参考和正式 PPT 视觉设计，并限定重复检查的范围。第三章沿用原有规则。

后续待工作流稳定后，共享文档及其他可复用材料的云端管理将作为下一阶段的主要升级目标。
