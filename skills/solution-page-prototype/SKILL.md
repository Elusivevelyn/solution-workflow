# PPT 页面原型

## 输入与任务

完整阅读 `03_文字方案/文字方案.md` 定稿。把分配到各页的业务内容转化为可审阅的上屏文案、图示和真实空间构图，保留相关图片、视频、截图位置。使用中性黑白灰，利用面积、字号层级、对齐和间距体现视觉主次；公司配色、字体及装饰风格在正式制作阶段应用。

## 页面规划

先梳理每章需要传达的内容，再安排页序，在 `04_PPT页面原型/页面规划.md` 记录页码、稳定 ID（如 P001）、标题或核心主题、大致内容、文字稿位置。按需注明本页表达任务及重要内容的移页去向。

顺读标题，处理语义跳跃、重复和不必要的单独成页。将规划表展示给用户，确认后直接进入原型；不增加一轮独立的逐页文案提案。封面留到正式 PPT 制作。第三章选材、组织和分页沿用现有规则，不因本版其他页面设计指导而重新改写。

页面 ID 与排序分开，调序无需重命名已确认页面。每页在规划中记录草稿或已确认及对应源文件即可，不创建额外项目状态系统。

## 逐页设计与显示

1. **先承接内容。** 从本页对应文字稿中带入应表达的主要内容、业务过程、关键细节及影响客户判断的条件。同页同时承担能力说明和应用示例时，两部分都要有空间。先建立完整内容，再决定如何表达，不从选中的版式反向挑少量文字。
2. **按页参考布局。** 读取 [内容与布局设计指引](references/layouts.md)，结合本页的表达任务、信息量和可用素材，定向查找 PPTNest 布局参考。相近检索可批量进行，适用参考可在组内复用；只借鉴区域组织、比例、图文关系与阅读路径。
3. **完成实际构图。** 展示最终上屏标题、正文、图示标签、连线和按比例预留的素材位置。用图形或空间已经表达的信息可省去重复解释，必要规则和条件保留为可读文字。标题和小标题单独顺读时，应能看出业务用途或关键结论。
4. **处理页面容量。** 先调整内容区域、图文比例和表达方式，再压缩冗余措辞。关键内容确需移到其他页面时，在页面规划注明去向；需要改变已确认页数或建设内容时，说明具体影响再确认。不以任意文字保留率或极小字号换取简洁。
5. **在对话中展示。** 原型为真实 16:9 视觉页面，容量与实际投屏相符，不用 ASCII、纯文本表格或布局说明替代成品。使用当前可用的对话内可视化能力，先读取其完整使用规范。用户无需下载或打开附件，不向其交付 HTML、DOCX、PDF 或 PPT。
6. **按组协作。** 逐页完成设计，按用户指定范围成组展示。用户反馈后只修改受影响内容；确认可以针对单页或一组页面，确认后集中归档，不重复要求逐页批准。

文字定稿是内容基准。允许重组和压缩表达，不擅自改变建设方向、功能边界或技术关系。原型中已经确认的内容与布局意图共同交给正式 PPT，不能只交一份精简文案。

## 原型自动保留与 PPT 交接

- 在项目 `04_PPT页面原型/work/draft/P001.html` 等位置保留每页的显示源文件。使用内嵌布局信息的 HTML 片段，页面根元素明确 16:9，标题、文字和图示关系可读取；禁止只保存一张整页截图作为唯一源文件。页面之间隔离样式，避免修改一页影响其他页。
- 对话内展示需要写入当前环境允许读取的可视化目录时，将同一份内容复制过去展示。展示副本不充当新的内容基准，不为适应显示而悄悄改掉项目源文件。
- 用户确认后，将对应显示源保存到 `work/confirmed/P001.html`，在页面规划注明已确认。后续试改使用 draft；未经用户确认不覆盖 confirmed。
- 已确认页再次修改并重新确认时才更新其 confirmed 文件。最终以页面规划的顺序和 confirmed 源文件为 PPT 输入，不从记忆重建、不要求人工截图、不强制再导出汇总附件。
- 只建立确有用途的工作文件。不自动生成截图集、PDF、单独分析报告或冗余存储系统。

正常展示时一并确认页面可以显示、保存源与展示内容一致即可，不另设试跑验收环节。若显示或保存失败，修复具体断点；不得把用户未见到或未确认的页面交给正式制作。

## 完成条件

每组展示前做一次检查：对照该组文字稿确认关键信息均有落点，图示表达实际关系，阅读路径和文字可读；通看相邻页的构图，处理没有内容理由的连续套版。修复后只复查受影响处，不反复做全量检查或输出检查报告。

待制作页均已确认、确认源可读后，将页面规划与对应源文件交给 [PPT 制作子 Skill](../solution-ppt-production/SKILL.md)。
