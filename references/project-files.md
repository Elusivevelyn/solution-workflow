项目按用户指定的 `PROJECT_*` 目录组织。新项目采用以下结构；只建立有当前用途的目录，不生成空白成果或虚构客户资料。

```text
PROJECT_项目名/
├── 00_项目需求/
│   ├── 需求原始资料/
│   └── 项目需求说明.md
├── 01_行业调研/
│   └── 行业调研笔记.docx
├── 02_内部调研与建设方向/
│   ├── 既往方案关键页/

├── 03_文字方案/
│   └── 文字方案.md
├── 04_PPT页面原型/
│   ├── 页面规划.md
│   └── work/                 原型阶段内部工作文件，非附件交付
│       ├── draft/            正在修改的页面源文件
│       └── confirmed/        用户确认时保存的页面源文件
├── 05_PPT制作/
│   └── 方案PPT初稿.pptx
└── 06_最终交付/
    └── 方案PPT最终版.pptx
```

页面原型通过 HTML 工作源自动保留，在对话内展示，详见 [页面原型子 Skill](../skills/solution-page-prototype/SKILL.md)。项目文件是制作依据，可视化目录中的副本只负责展示。用户确认后保存对应源文件，不要求人工截图或另外整理附件。

## 输入输出

| 工作 | 输入 | 写回 |
| --- | --- | --- |
| 需求整理 | 用户提供的需求与原始资料 | 项目需求说明；记录任务、障碍、期望变化，将关键缺口转为研究任务 |
| 对外调研及人工笔记 | 需求、前轮笔记、用户新问题 | 更新同一行业调研笔记，保留具体做法、适用条件、出处和人工填写内容 |
| 对内调研 | 完整行业笔记、SHARE 产品资料、按需补充的内部资料 | 在建设方向文档中保留能否实现、现有功能如何实现及扩展可能与依据 |
| 确认建设方向 | 需求阶段的问题、内外调研结果 | 在同一建设方向文档中写回结论、方案主线、模块与范围，经讨论确认 |
| 第二章设计 | 主动回读的完整笔记、内部实现材料、已确认框架 | 在文字方案内组织业务与价值、典型任务、总体架构及具体建设内容 |
| 完整方案 | 第二章设计、研究依据和相关产品资料 | 完善第一章、第四章；第三章沿用现有规则，最终按章节顺序形成文字定稿 |
| 原型 | 文字定稿、逐页定向布局参考及已有素材 | 页面规划及确认页面；主要内容、业务过程、关键细节和条件均有落点 |
| PPT | 确认页面、公司模板、新版制作 prompt | 可编辑初稿，方便人工填图 |
| 最终交付 | 初稿与人工素材 | 用户完成终版；只有实际获得终版文件才记录其已存在 |

建设范围与内部实现材料写在模块框架和文字方案中，页面顺序、移页去向与确认情况写在页面规划中即可。不另建项目状态、决策管理、资料分类或内部调研总结文件。

`SHARE` 是公司产品和通用素材库，不要求用户将行业研究积累放入特定新目录。现阶段行业研究成果先留在各项目内；用户要求跨项目复用时再按其指定位置保存。
